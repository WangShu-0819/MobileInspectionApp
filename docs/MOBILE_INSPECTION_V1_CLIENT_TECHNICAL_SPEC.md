# 手机工业零件视觉质检系统 V1 客户技术规格书

版本：V1.0  
项目名称：手机工业零件视觉质检系统  
交付形态：Android 手机端视觉质检工作台

## 1. 项目目标

系统面向工业零件现场质检，使用手机完成零件识别、模板加载、标准视角取景、现场拍照、模板与实拍图比对、检测结果生成、历史追溯和结果导出。

系统最终形成以下完整工作闭环：

```text
建立或导入模板
  → 确定零件
  → 加载零件模板
  → 按 View 1 到 View N 的顺序取景和拍摄
  → 模板与现场照片比对
  → 确认本次检测区域
  → 执行检测算法
  → 输出检测结果
  → 保存检测记录
  → 查询历史记录和导出结果包
```

系统的核心目标是帮助质检人员稳定复现标准拍摄位置，并对模板规定的检测区域进行可追溯检测。

## 2. 应达到的技术指标和参数

### 2.1 总体功能指标

| 功能要求 | 技术参数及验收指标 |
|---|---|
| Android 手机端前端系统 | 支持 Android 8.0（API 26）及以上版本；应用名称为“视觉质检”；支持模板管理、零件管理、现场采集、检测结果、追溯记录和结果导出等功能。 |
| 零件识别 | 支持人工选择零件、使用 DPM 实时扫码确定零件，并可使用钢印 OCR 辅助确认；DPM 扫码命中已绑定的零件后，自动加载该零件对应的模板。 |
| 模板管理 | 每个零件支持一个或多个检测视角（View）；每个 View 绑定一张参考图片和对应检测区域；支持保存 View 顺序，重新进入应用后保持不变。 |
| 现场采集 | 按当前零件的 View 顺序，从 `View 1/N` 至 `View N/N` 逐一拍摄；每个 View 成功保存一张真实现场照片。 |
| 模板辅助取景 | 在实时相机画面上叠加模板参考图，支持调节透明度和显示/隐藏模板，辅助操作人员复现标准拍摄位置。 |
| 拍后比对 | 支持在模板图与实拍图之间直接切换、进行透明叠加和快速交替查看；支持放大、缩小和平移，查看局部细节。 |
| 基于检测区域的检测 | 按照模板中配置的检测区域和检测算法执行检测，并保存本次检测实际采用的区域。 |
| 检测结果 | 输出总体检测结果和各检测区域结果，结果状态至少包括 `PASS`、`REVIEW`、`FAIL`、`ERROR`。 |
| 追溯记录 | 保存零件、模板、模板版本、现场原图、检测区域、算法、参数、评分值、结果状态、检测时间和异常信息。 |
| 结果导出 | 生成包含结果清单文件（manifest.json）、Excel（.xlsx）文件、原始图片、结果图片、检测区域图片、配置快照、检测状态和错误信息的完整结果包。 |

### 2.2 图像采集和相机参数

| 功能要求 | 技术参数及验收指标 |
|---|---|
| 相机框架 | 统一使用 Android CameraX 相机框架；全系统由同一相机控制器统一管理相机连接、预览、分析和拍照。 |
| 后置摄像头 | 使用普通 Android 手机后置主摄像头，不配置专用工业相机；验收时，指定手机应在规定工作距离内完整拍摄零件及全部检测区域。 |
| 图像比例 | 预览、分析和拍照优先使用 4:3 图像流；竖屏显示时，图像按 3:4 比例完整显示。 |
| 拍照分辨率 | 支持指定 Android 手机后置主摄输出 4:3 拍照图像；以指定手机在甲方样本和现场条件下清晰覆盖全部检测区域为验收依据，不统一规定具体像素数。 |
| 图像格式 | 现场照片采用 JPEG 格式保存；照片必须可解码、宽高有效、方向信息正确，不产生空文件或残留临时文件。 |
| 实时预览与分析 | 预览和实时分析分别使用独立的 CameraX 图像流，分辨率由终端设备协商确定；当前验证设备的分析流约为 1440×1080（4:3）。画面应连续显示并保持正确纵横比，不得裁切或拉伸，也不得将黑边区域作为相机内容。预览帧率由终端 CameraX 能力决定，建议在指定验收设备上稳定达到不低于 15 fps。 |
| 拍摄视野 | 不统一规定镜头视场角数值；在规定工作距离下，零件主体、模板范围和全部关键检测区域必须完整进入相机有效内容区域，不得裁切、遮挡或明显变形。 |
| 内容区域 | 系统记录真实相机有效内容区域（`contentRect`）；模板、取景辅助信息和后续坐标映射只作用于有效图像区域，不覆盖黑边区域（letterbox）。 |
| 拍照响应 | 点击主拍照按钮后调用真实 ImageCapture 链路；每次成功拍照仅推进一个 View，保证每个 View 最终仅保存一张正式现场照片。 |

### 2.3 模板透明叠加参数

| 参数 | 指标 |
|---|---|
| 模板图片 | 使用模板原始参考图片，保持原始宽高比。 |
| 透明度范围 | 0%～80%。 |
| 默认透明度 | 45%。 |
| 0% 状态 | 完全显示现场相机画面。 |
| 透明叠加范围 | 仅覆盖相机有效 `contentRect`，不覆盖黑边区域。 |
| 图像显示模式 | 支持原比例显示和在有效内容区域内撑满显示；两种模式均不得拉伸图片。 |
| 显示控制 | 调节透明度和显示模式只改变界面显示效果，不重新创建 CameraX 会话，也不影响已保存的原图。 |

### 2.4 模板和检测区域参数

| 功能要求 | 技术参数及验收指标 |
|---|---|
| 零件与模板关系 | 一个零件可关联一个或多个有序检测视角（View）；每个 View 关联一张参考图和一组检测区域。 |
| 模板检测区域 | 模板检测区域（Template ROI）用于定义标准检测区域的位置、尺寸、坐标系、关联算法和检测参数。 |
| 本次检测区域 | 根据模板检测区域映射生成本次检测区域（Session ROI）；操作人员可调整本次检测区域的位置、宽度和高度。 |
| 模板保护 | 对本次检测区域（Session ROI）的调整只影响当前检测，不修改模板标准检测区域。 |
| 坐标一致性 | ROI 坐标必须基于原始图片的尺寸、方向和坐标系；模板导入时，无法确认区域坐标含义的区域不得导入。 |
| ROI 边界 | ROI 不得超出对应图片的有效范围；发生越界、缺图或坐标异常时，应返回明确的错误状态。 |
| 算法关联 | 每个检测区域至少配置检测目标、算法类型、算法参数、阈值以及是否为关键检测区域。 |

### 2.5 检测算法和结果参数

| 功能要求 | 技术参数及验收指标 |
|---|---|
| 算法管理 | 系统统一注册和调用检测算法；新增算法接入时不改变既有调用接口。 |
| 首个通用算法 | 支持对模板 ROI 与实拍 ROI 进行结构差异分析或相似度分析，并输出评分值（Score）和判定状态。 |
| 专项算法扩展 | 检测框架可扩展螺栓存在、孔位、螺纹和缺件等专项检测算法。 |
| 输入数据 | 使用真实现场原图、当前检测区域（Session ROI）和对应模板检测区域（Template ROI）；不得使用固定假图或固定假坐标替代实际输入。 |
| 评分值（Score） | 保存算法输出的评分值、算法名称、算法版本和参数快照；评分值的取值范围、含义和判定阈值由具体算法配置定义。 |
| PASS | 检测结果满足配置阈值，结构与模板基本一致。 |
| REVIEW | 存在一定差异，需要人工复核。 |
| FAIL | 差异明显，未满足检测要求。 |
| ERROR | 图片、检测区域、算法、参数或数据链路异常，无法得出可靠检测结论。 |
| 总体结果 | 按业务规则汇总各检测区域结果。关键检测区域判定为 FAIL 时，总体结果可按规则判定为 FAIL；ERROR 必须保持为检测异常并明确提示。 |

## 3. 模板数据和导入要求

### 3.1 模板数据结构

每个模板中的检测视角（View）至少包含以下内容：

- 模板名称；
- 所属零件；
- View 的唯一标识和显示顺序；
- 参考图片；
- 图片宽度、高度和方向信息；
- 模板检测区域（Template ROI）列表；
- 检测区域关联的算法及参数；
- 模板版本和更新时间。

### 3.2 既有模板复用

系统优先复用既有模板数据，通过模板导入服务迁移至当前系统。

导入规则：

1. 保留零件、检测视角和参考图片的对应关系。
2. 保留 manifest.json 文件中的显式检测视角顺序。
3. 对 View 顺序缺失或重复的情况使用稳定规则处理，保证重复导入结果一致。
4. 模板图片保存到应用私有存储空间。
5. 原有检测区域（ROI）只有在原始尺寸、方向和坐标语义确认后才自动转换。
6. 导入失败后不得留下半成品模板、空图片或临时文件。

## 4. 最终用户操作流程

### 4.1 管理员配置流程

```text
创建或导入零件
  → 导入模板参考图片
  → 设置 View 顺序
  → 配置模板检测区域（Template ROI）
  → 选择检测算法和参数
  → 保存模板版本
```

### 4.2 现场检测流程

```text
人工选择零件、使用 DPM 扫码，或通过 OCR 辅助确认零件
  → 自动加载对应模板
  → 进入 View 1/N
  → 打开模板透明叠加
  → 调整手机位置和距离
  → 拍摄当前 View
  → 进入模板图与现场图比对页面
  → 确认或微调本次检测区域（Session ROI）
  → 执行当前 View 检测
  → 继续下一个 View
  → 汇总检测结果
  → 保存检测会话（Inspection Session）
```

### 4.3 历史查询与导出流程

```text
进入追溯记录
  → 按零件、时间或结果筛选
  → 查看检测详情
  → 查看原图、模板、检测区域、算法和评分值
  → 人工复核
  → 导出完整结果包
```

## 5. 数据保存和追溯要求

每次正式检测形成一个检测会话（Inspection Session）。记录至少包括：

| 数据类别 | 保存内容 |
|---|---|
| 零件信息 | 零件编号、名称、DPM 绑定码、识别方式 |
| 模板信息 | 模板编号、检测视角信息、模板版本和参考图引用 |
| 图像信息 | 原始现场照片、图片尺寸、方向、文件校验信息 |
| 检测区域信息 | 模板检测区域（Template ROI）、本次检测区域（Session ROI）、坐标系、位置和尺寸 |
| 算法信息 | 算法名称、版本、参数、阈值和评分值（Score） |
| 结果信息 | 总体结果、各检测区域结果和人工复核结果 |
| 过程信息 | 检测时间、设备信息、应用版本 |
| 异常信息 | 错误状态、错误码、错误原因和处理记录 |

历史记录必须保存检测时使用的模板、检测区域、算法和参数快照。模板后续发生修改时，历史检测结果仍应能够解释和追溯。

## 6. 结果包格式

导出结果时生成完整结果包，目录结构如下：

```text
inspection-result-package/
├── manifest.json
├── inspection-result.xlsx
├── original-images/
├── result-images/
├── roi-images/
├── template-snapshot/
└── errors/
```

结果包至少应包含：

- 检测会话（Inspection Session）编号和导出版本；
- 零件、模板和 View 信息；
- 原始现场图片；
- 模板参考图片；
- 检测区域图片及坐标；
- 检测算法、参数和评分值；
- 总体及各检测区域结果；
- 配置快照；
- 错误信息和人工复核信息；
- 图片文件路径、大小和校验信息。

只有在结果包内的文件全部生成并通过完整性检查后，系统才可显示“导出成功”。

## 7. DPM 与 OCR 技术要求

### 7.1 DPM

- 使用手机相机进行实时扫码。
- 扫码成功后根据绑定关系查找对应的已绑定零件。
- 命中已绑定零件后自动切换零件和模板，并从 View 1/N 重新开始采集。
- 对于未绑定的编码，提示用户先在模板配置中完成绑定。
- 模板配置支持 DPM 绑定和更换绑定。
- 同一个 DPM 码不得同时绑定多个零件。
- 复用统一相机控制器和既有 DPM 解码处理链。

建议验收指标：

| 指标 | 建议目标值 |
|---|---|
| 识别对象 | 甲方提供并确认的 DPM 样本集 |
| 识别范围 | 扫码框内有效 DPM 码 |
| 响应时间 | 从 DPM 码稳定进入扫码框到显示识别结果，建议不超过 2 秒 |
| 误识别 | 扫码框外的码不得触发绑定或零件切换 |
| 绑定冲突 | 冲突绑定必须拒绝并保留原绑定关系 |

最终识别率和响应时间应根据甲方确认的现场样本、光照、距离和角度条件进行验收。

### 7.2 钢印 OCR

- 使用手机相机实时采集钢印图像。
- 输出识别文本和必要的文本区域信息。
- OCR 结果用于辅助确定零件，不直接替代模板检测结果。
- 识别失败时显示可理解的提示，不生成虚假零件匹配。

## 8. 终端设备和部署建议

以下参数用于终端选型和现场部署。最终配置由甲方根据零件尺寸、拍摄距离和现场环境确认：

| 项目 | 建议参数 |
|---|---|
| 操作系统 | Android 8.0 及以上，建议 Android 12 及以上 |
| 处理器 | 64 位多核移动处理器，支持 CameraX 和 ML Kit |
| 内存 | 建议 RAM 不低于 6 GB |
| 存储 | 建议可用空间不低于 20 GB；实际容量根据模板和历史图片数量确定 |
| 后置摄像头 | 普通 Android 手机后置主摄，建议不低于 12 MP，支持 4:3 原始图像输出；最终以指定手机现场取景效果验收 |
| 屏幕 | 建议分辨率不低于 1080×2340，便于查看模板叠加和 ROI 细节 |
| 网络 | 支持 2.4 GHz / 5 GHz Wi-Fi；现场检测和本地图片保存不依赖持续网络连接 |
| 电源 | 建议电池容量不低于 5000 mAh；连续工作时长需按指定设备、亮度和拍摄频率实测确认 |
| 拍摄条件 | 由甲方确认零件尺寸、手机型号、拍摄距离和角度范围；现场应避免强反光、严重遮挡、极暗或过强光照 |

## 9. 性能和可靠性验收指标

以下指标可作为甲方验收条款中的目标值：

| 指标 | 建议目标值 | 验收方式 |
|---|---|---|
| 应用启动 | 冷启动后进入主界面，建议不超过 3 秒 | 指定设备连续测试 10 次，取平均值和最大值 |
| 模板加载 | 从已导入模板进入现场采集并显示首个 View，建议不超过 2 秒 | 使用指定模板和指定设备测试 |
| View 顺序 | 按 `displayOrder` 顺序加载和拍摄，顺序正确率 100% | 使用显式、缺失、重复顺序模板测试 |
| 拍照完整性 | 每个 View 保存 1 张可解码的原始 JPEG，不产生空文件和临时残留 | 连续拍摄完整模板并检查文件 |
| 页面稳定性 | 连续完成至少 10 次现场采集页面的进入和退出，无崩溃、黑屏或相机占用 | 真机循环测试 |
| 数据一致性 | 关闭并重新启动应用后，零件、模板、检测视角顺序和历史数据保持一致 | 重启和数据库复核 |
| 检测结果 | 每个检测区域均有明确的状态、评分值或错误信息 | 使用正常、差异和异常样本测试 |
| 导出完整性 | 结果包内的 manifest.json、Excel 文件、图片、检测区域图片和配置快照均可读取 | 解压并逐项校验 |
| 异常处理 | 相机、存储、图片、算法或导出失败时显示明确错误，不生成假结果 | 故障注入和异常样本测试 |

相关数值指标应在甲方提供正式样本并确认指定终端后最终确定；在现场条件尚未确认前，建议在合同或验收表中标记为“目标值”。

## 10. 交付验收主流程

甲方验收时应至少完成以下一条完整的真实业务链路：

```text
导入正式模板
  → 选择或扫码确定零件
  → 按顺序加载全部 View
  → 完成 View 1 到 View N 拍摄
  → 查看模板与实拍图
  → 确认检测区域
  → 执行至少一种真实检测算法
  → 查看总体和各检测区域结果
  → 保存历史记录
  → 导出并校验完整结果包
```

验收不得使用固定假图片、固定假坐标、假检测状态或未实际生成的导出文件替代真实流程。

## 11. 最终交付形态

最终交付的系统应是一套完整的手机工业零件视觉质检工作台：

- 管理员可以创建和维护零件模板；
- 现场人员可以快速确定零件并按标准视角完成拍摄；
- 模板透明叠加可帮助现场人员稳定取景；
- 拍摄后可以清晰查看模板与实拍差异；
- 检测区域和算法配置可解释、可追溯；
- 系统可以输出清晰明确的检测结果；
- 每次检测都能保存完整历史记录；
- 结果可以导出为便于人工查看、追溯和分析的完整结果包。

最终验收的核心判断标准是：

```text
模板可用 → 人员可准确取景 → 照片可比对 → 检测区域可确认
→ 算法可执行 → 结果可解释 → 历史可追溯 → 数据可导出
```
